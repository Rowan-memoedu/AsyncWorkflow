# 分类录音、Document 与续录

普通单人录音默认整体整理。只有原文明确要求分成独立记录或分别归档时才拆分；话题、日期、事项类型的变化不触发拆分。引用、否定或讨论“分割”也不算分割指令。每份输出仍校验原文覆盖范围，已有成功结果不重跑。

## RemNote 目录与提示词

本机 `refinement-tags.json` 绑定三个准确的 tag ID：`writing`、`non_writing`、`automatic`。已标记的 Document 及其下级 Document 自动进入手机目录；普通正文节点不成为独立入口。文档改名、移动、直接 tag 修改及新增子 Document 随目录同步生效，旧录音文件名中的路由键保持稳定。模板复制出的 Daily Note 和知识库根级 trash 下的文档不进入独立目录。

- 直接带写作 tag：使用写作提示词，跳过 Decision。
- 直接带非写作 tag：使用非写作提示词，跳过 Decision。
- 自动判断、没有分类 tag 或两个分类 tag 冲突：进入 Decision。子 Document 不继承父文档的转写类型。
- 根入口移除全部录音 tag 后退出目录；要保留入口但取消预设类型，改为自动判断 tag。历史路由绑定保留，避免已录文件被转投其他文档。

手机端任意层级可新建有名称的真实 Document。普通目录在对应文档下新建；Daily Note 目录写入每日模板，归档时确保当天对应分支也是 Document。离线请求先持久保存，恢复连接后幂等创建并回读，再归档录音；录音先到而目录未到时等待重试。

## 续录的状态边界

手机保存 hold 请求和新增段，后台按原录音 SHA-256 暂停后续副作用。最终写入与 hold 共用互斥锁，已提交、未知或完成的效果均不能合并。原录音已有处理结果时，新增段单独保存。

未处理的原录音与新增段在手机端按时间顺序合并。当前合并支持相同声道、采样率和编码设置的 M4A/AAC，不重新编码。合并校验通过后，后台先将旧录音标记为已替代；手机再导出新文件，并校验、保存旧文件的回收站副本后移走旧文件。中断可按原请求 ID 续办；不以超时视为成功。格式不兼容或合并失败时保留原文件，可将新增段保留为独立录音。

## 服务与验证

沿用已有录音查看服务。`phone` 凭据可提交有严格字段限制的目录/续录请求；`desktop` 凭据仍只读。后台发布凭据负责读取请求、回传结果和发布目录。接口不接收音频、任意命令、文件路径或自定义网址，拒绝浏览器跨站提交。电脑在线时约 5 秒检查控制请求、约 60 秒同步目录；手机前台约 15 秒刷新，后台由 Android JobScheduler 重试。

兼容版本：Android 19、独立 RemNote 插件 0.1.13。更新次序为后台保护逻辑与插件、服务器接口、手机 APK。重启后台前检查活跃 Prefect flow；旧插件资源与服务器 release 链接保留用于恢复。

本地验证：`python -m pytest -q`；插件 `npm run check`、`npm test`、`npm run build`；合成文本模型检查 `python scripts/capture_split_canary.py --output <artifact-directory>`。Android 的合并、历史回收、离线目录与布局使用隔离 debug 安装的 instrumentation 测试。
