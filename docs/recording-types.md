# 录音类型标准

本文件是录音类型判断的本地依据，可增量修改。修改规则后，已完成的录音仍跳过；未完成任务复用成功环节。

## 普通录音

- 文件名整体只包含日期和时间，使用项目已有日期格式。
- 时长严格小于 20 分钟。
- 根据转写内容确认是单人自述：个人记录、灵感、口述任务或给助手的指示都可以；引用别人说的话不等于多人交流。
- 不做声纹身份校验，也不额外识别、标注对话人。
- 明显多人轮流交流或无法确认单人自述时，不进入标准工作流，保留音频和已有转写，日志注明原因。
- 普通日期文件名始终不归入交流录音。通过准入后沿用现有内容／命令分流和归档规则。

## 交流录音

- 文件名不是普通日期格式，且来源或名称能识别为微信通话、电话等交流录音。
- 目前只处理配置中已确认的交流对象；新增对象在本机配置中增量维护，不按所有非日期文件名一概处理。
- 不受普通录音的 20 分钟限制，完整内容均需保留。
- 沿用已有冻结提示词做结构化整理，不另加对话人区分、逐字稿或摘要流程。
- 整理后的整块正文放到“内部会议预案 → 实际录音日期 → 会议记录”；缺失的日期 document 或会议记录节点由独立插件创建。
- 录音文件名中的完整时间优先于云端上传时间；否则采用可验证的来源时间。已有日期 document 使用 M.D 名称，新日期使用 YYYY-MM-DD，以免跨年重名。
- 交流中的任务、指示和工作流讨论均作为会议正文保留，不调用命令执行或自反馈分流。
- 每块正文上下各有一个同级空节点；来源、时间、分类和处理状态只存日志。

## 重复与部分完成

- 以音频字节的 SHA-256 标识录音；改名、重新下载和重复批次不能重复处理。
- 完整结果已落地的录音直接跳过，不补跑新分类、不重新转写或重复归档。
- 已有原生任务正在运行、暂停或等待时沿用该任务。失败或崩溃时重试同一个原生任务，保留已确认的外部动作回执。
- 部分完成复用已有转写、类型判断、结构化正文、分块与成功归档；只推进缺失或失败环节。
- 未知提交结果先核对，不能盲目重放；用户修改过的节点不能被覆盖。
- 每次提交的跳过、沿用或续跑结论留在录音处理日志中。自动新增录音入口是否开启是独立开关。
